# プログラミング原則

対象は実コード（Rust・TypeScript）とハーネス（シェルスクリプト・フック・Node スクリプト）のすべて。
**SOLID・テスト可能性・YAGNI は厳守事項**であり、守れない場合は実装より先に理由を PR に書き、メンテナの合意を得る。

## 1. SOLID（厳守）

| 原則 | 守ること | このリポジトリでの具体例 |
| --- | --- | --- |
| **S** 単一責任 | 1 つのモジュール・関数が変わる理由は 1 つだけ | フックは「入力を取り出す → `policy_*` で判断 → 結果を返す」だけ。判断は `scripts/lib/policy.sh`、入出力は `scripts/lib/hook-io.sh` |
| **O** 開放閉鎖 | 振る舞いの追加は既存コードの書き換えではなく、追加で行えるようにする | ルールは 1 つ 1 関数（`policy_git_push`・`policy_git_bulk_add` …）。新ルールは関数を足して束ね直す |
| **L** リスコフ置換 | 抽象（trait・interface・関数の契約）を実装するものは、呼び出し側の期待を裏切らない | `policy_*` はすべて「0 = 問題なし／1 = 違反＋理由 1 行」の契約を守る |
| **I** インタフェース分離 | 使わないメソッドへの依存を強いない。小さく役割ごとのインタフェースにする | `harness_load hook-io` のように必要なアダプタだけを読み込む |
| **D** 依存性逆転 | 方針（判断）は詳細（I/O・外部サービス・リポジトリ固有の値）に依存しない。詳細を外から渡す | リポジトリ固有の値は `scripts/harness.conf`、API の場所は `HARNESS_GITHUB_API` で注入。共有コードは値の出どころを知らない |

## 2. テスト可能なコード（厳守）

- **判断と I/O を分ける。** 純粋関数（入力 → 出力）に判断を集め、ファイル・プロセス・ネットワーク・時刻・乱数は境界のアダプタに押し出す。
- **依存は引数・環境変数・trait / interface で注入する。** テストのためだけの分岐（`if test_mode`）は書かない。
- **グローバルな状態を読み書きしない。** 必要なら明示的に受け渡す。
- **すべてのスクリプト・フックに対応するテストを置く**（`tests/harness/**/<name>.bats`）。無いと `scripts/check-principles.sh` が失敗する。
- 外部コマンドに依存する処理は、`PATH` に置いたスタブや `file://` の URL で置き換えて結合テストできる形にする。

## 3. YAGNI（厳守）

- **今必要な機能だけを作る。** 「将来使うかもしれない」引数・設定・抽象・プラグイン点は作らない。
- 抽象化は**同じ形の重複が 3 回目に現れたとき**に行う（2 回目までは重複を許す）。
- 使われていないコード・設定・依存は削除する。コメントアウトして残さない。
- 将来の拡張が確実な場合も、まず ADR に記録し、実装は必要になった時点で行う。

## 4. 可読性・保守性

- **名前で意図を伝える。** 略語より完全な語を使う。真偽値は `is_` / `has_`、検査関数は「何を検査するか」を名前にする。
- **短く保つ。** シェル関数は 30 行、スクリプトは 120 行、Rust 関数は 40 行（clippy `too_many_lines`）が上限。超えたら責務を分ける。
- **早期リターンでネストを浅くする。**
- **コメントは「なぜ」を書く。** 「何をしているか」はコードで表す。
- **エラーは握りつぶさない。** Rust は `Result`、TypeScript は型付きの例外、シェルは `set -euo pipefail` と明示的な終了コード。
- **定数・設定は 1 か所に置く。** 同じ正規表現や値を複数ファイルに書かない。
- 周辺コードの命名・コメント密度・イディオムに合わせる。

## 5. 言語ごとの補足

| 言語 | 補足 |
| --- | --- |
| Rust | `unsafe` 禁止。`unwrap` / `expect` はテスト以外で使わない。公開 API には doc コメント。trait で依存を抽象化する |
| TypeScript | `strict` + `noUncheckedIndexedAccess`。`any` を使わない。副作用のある処理はモジュール境界に寄せる |
| シェル | `set -euo pipefail`。共有ロジックは `scripts/lib/` の関数、リポジトリ固有の値は `scripts/harness.conf`。ShellCheck の警告をゼロにする |

## 6. ハーネスで強制する項目

| 項目 | 仕組み |
| --- | --- |
| スクリプト・フックごとのテストの有無 | `scripts/check-principles.sh`（テスト可能性） |
| シェル関数・スクリプトの長さ | `scripts/check-principles.sh`（単一責任の目安） |
| Rust 関数の長さ | clippy `too_many_lines`（`clippy.toml` で上限 40 行） |
| シェルの静的解析 | ShellCheck（警告ゼロ） |
| Rust の静的解析 | clippy `-D warnings`、`unwrap_used` / `expect_used` |

O・L・I・D と YAGNI は機械では判定できないため、**変更のたびに下のチェックリストで自己レビュー**し、PR テンプレートの該当項目に答える。

## 7. 変更前後のチェックリスト

- [ ] この変更が変える理由は 1 つか（S）
- [ ] 新しい振る舞いを既存コードの書き換えではなく追加で入れたか（O）
- [ ] 既存の契約（戻り値・終了コード・型）を守っているか（L）
- [ ] 使わないものへの依存を増やしていないか（I）
- [ ] 判断ロジックが I/O やリポジトリ固有の値に直接依存していないか（D）
- [ ] 判断ロジックを I/O なしで単体テストできるか（テスト可能性）
- [ ] 今必要でないものを作っていないか（YAGNI）
