# ADR-0023: 同じフォルダを複数の版で開いても、ファイルを壊さない

- 状態: 提案
- 日付: 2026-11-06
- 関連する ADR: ADR-0001（テキストが唯一の正本）、ADR-0005（配置ファイル）、ADR-0018（プラグインのホスト）、ADR-0019（プロジェクト）、ADR-0020・ADR-0022（公開の系列）

## 背景

ADR-0022 で、安定版・リリース候補版・プレビュー版の 3 つを同時に公開する。
ブラウザの保存領域は系列ごとに名前を分けている（ADR-0020）。しかし、利用者のフォルダの中のファイルは分けられない。
同じフォルダを、ある日は安定版で、次の日はプレビュー版で開くことは普通に起きる。そして古い系列には修正を出さない（ADR-0022）。
つまり、新しい版が書いたファイルを古い版がどう扱うかは、**その古い版を出す前に**決めておくしかない。

今の版で、実際に次のことが起きる。

- 0.2.0 は、線の調整（ADR-0005 の配置ファイルの `@bends`・`@anchors`）を書くが、形式の番号は 0.1 と同じ `1` のままにしている。
- 0.1.0-rc.1 は、知らない項目を読み飛ばし、保存するときに書かない。
- そのため、0.2.0 で線を調整した図を 0.1.0-rc.1 で開き、要素を 1 つ動かして保存すると、線の調整が何の知らせもなく消える。
- 0.1.0-rc.1 は、形式の番号が違う配置ファイルを「対応していません」として空の配置で開く。その後に要素を動かして保存すると、新しい版の配置ファイルを上書きしてしまう。

一方、プロジェクトの設定（`modelith.json`）は、0.1.0-rc.1 から既に知らない項目を残して書き戻している（ADR-0019）。

他のプロジェクトの形式は、次のように古い版から守っている。

- **知らない項目を、保存するときに書き戻す**：Protocol Buffers、Jupyter の nbformat、Excalidraw、Kubernetes の API
- **古い版が理解しなければならない機能に印を付け、知らなければ止める**：git の `extensions.*`、OOXML の `MustUnderstand`
- **新しい版で書かれたファイルを古い版が上書きしようとしたら確かめる**：Blender、SQLite

## 決定

### 1. 守ること

**新しい版が書いたものを、古い版が壊さない。** 壊さないとは、黙って消さない・黙って上書きしないことを言う。
古い版が新しい機能を使えないのは構わない。できないときは、利用者にそう伝える（言葉は ADR-0014 に従う）。

### 2. テキスト（`.sysml`）

- テキストは正本なので（ADR-0001）、古い版は、読めない構文をエラーとして見せるだけにする。テキストを作り直したり、整形し直したりしない。
- 図や画面からの変更は、今までどおり変える範囲だけの `TextEdit` にする（ADR-0001）。読めない構文の範囲は変えない。

### 3. 横に置くファイル（配置ファイル・プロジェクトの設定・これから足すもの）

JSON で書く横のファイルには、すべて次の決まりを当てはめる。

- **知らない項目を残す。** 読むときに知らない項目は、保存するときにそのまま書き戻す。
  - 配置ファイルでは、いちばん外側の項目と、ビューの中の `@` で始まる項目が対象になる。
  - `modelith.json` は既にこの形になっている。
- **古い版が守れない機能には印を付ける（`requires`）。** 新しい項目のうち、古い版が残すだけでは中身が食い違うものは、ファイルの `requires` にその機能の名前を書く。
  - 書くのは、その機能を実際に使ったときだけにする。
  - 古い版は、`requires` に知らない名前があれば、読める部分を表示に使い、そのファイルを保存しない。
  - 保存しないことは、「このファイルは新しい版で作られた機能を含むため、この版では保存しません」のように知らせる。
  - 線の調整（`@bends`・`@anchors`）は、要素の位置と組で意味を持つ。古い版で要素だけを動かすと線が食い違うので、`requires` に入れる。
- **古い版が読み違える変更だけ、形式の番号（`format`）を上げる。**
  - 古い版は、知らない番号のファイルを読まない。
  - 空の中身で上書きもしない（今の 0.1.0-rc.1 の動きを改める）。
- **読めなかったファイルは上書きしない。** 壊れていて読めないときも、番号が違うときも、そのファイルを保存しない。

### 4. ブラウザの保存領域

- 系列ごとに名前を分ける（ADR-0020 と ADR-0022。安定版は付けない、`@rc`、`@preview`）。
- 同じ系列の中でも、取り下げ（ADR-0022 の 4）で古い版に戻ることがある。古い版は、知らない形の記録（IndexedDB の新しい版を含む）を見つけたら、消さずに使わない。そのとき、そのことを知らせる。

### 5. プラグインのマニフェスト

- マニフェストは知らない項目を拒む（plugin-sdk の `deny_unknown_fields`）。
- プラグインが「動く本体の版の範囲」を書ける任意の項目を plugin-sdk に足し、本体はその範囲の外ではプラグインを動かさずに知らせる。
- 古い本体には、後から新しい項目を教えられない。そのため、この項目は 0.1.0 より前に入れる。
- 項目の名前と範囲の書き方は、plugin-sdk の変更と ADR-0018 の改訂で決める。

### 6. テスト

- **見本のファイルを置く**：新しい版が書くファイルの見本（知らない項目を含むもの、`requires` を含むもの、形式の番号が大きいもの）を、テストの資料として置く。
- **往復を確かめる**：見本を読み込んで保存し直したときに、知らない項目が残ること、`requires` と番号を守って保存しないことを確かめる。
- **見本を足す時期**：新しい項目を足すときは、同じ PR で見本も足す。見本は `main` と `dev` の両方に置く。古い版のテストに、新しい版の見本が入る。

### 7. 0.1.0 に入れるもの

ADR-0022 の 6 の手順で、`0.1.0-rc.2` に次のものを入れる。

- 配置ファイルの知らない項目を残す・`requires` を読む・読めなかったファイルを上書きしない（3）
- 保存領域の知らない形の記録を消さない（4）
- プラグインのマニフェストの、本体の版の範囲（5）

あわせて、`dev`（0.2.0）は、線の調整を使った配置ファイルに `requires` を書く。

## 結果

- 安定版・リリース候補版・プレビュー版で同じフォルダを開いても、新しい版の内容が黙って消えたり上書きされたりしない。
- 古い版では、新しい機能を使ったファイルの一部が保存できなくなることがある。そのときは利用者に知らせる。
- 新しい項目を足すたびに、`requires` に入れるかを決め、見本を足す手間が増える。
- 0.1.0 の正式版が rc.2 を経るので、出るのが少し遅れる。
