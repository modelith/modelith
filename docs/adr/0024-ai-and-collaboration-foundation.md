# ADR-0024: AI と共同編集の土台（外に出す操作と、変更の記録）

- 状態: 提案
- 日付: 2026-11-12
- 関連する ADR: ADR-0001（テキストが唯一の正本）、ADR-0004（プラグインの構成）、ADR-0006（ライセンス）、ADR-0016（Rust のモデルと Worker）、ADR-0021（複数のファイルにまたがるモデル）、ADR-0025（サーバの境目）、ADR-0026（利用状況の送信）

## 背景

0.3.0 から、AI と、ほかの人と、一緒にモデルを作れるようにする（[リリース計画（0.3.0 から先）](../development/release-plan-0.3.0.md)）。
AI（Claude・Codex など）は MCP でモデルを読み書きし、ほかの人はサーバ越しに同じモデルを編集する。どちらも、利用者の画面の外からモデルを変える。

今の Modelith で、外から使える口と、足りないものは次のとおり。

| 観点 | 今の状態 | 足りないもの |
| --- | --- | --- |
| 読む | コア（Rust）が解析・モデル構築・検査をする。CLI は `modelith check <フォルダ>` だけ | 要素の一覧・中身・図の一覧を返す口 |
| 書く | 画面の操作は「編集の意図」（`Intent`：要素を足す・名前を変える・消す・関係を足す・説明を書く など）としてコアに渡し、コアが `TextEdit` を作る（ADR-0001・ADR-0016） | 画面の外から意図を渡す口。意図は図の要素のキー（`u:…`・`l:…` と図の文脈）で要素を指すので、外からは修飾名で指せる必要がある |
| 図 | 図の中身（どの要素と線を描くか）はコアが作る。**配置（`geometry.ts`）と描画（`svg.ts`）は Web アプリの TypeScript にある** | 画面を介さずに図を書き出す口 |
| 契約 | plugin-sdk にマニフェスト・`TextEdit`・診断・プラグインのメッセージがある（ADR-0004・ADR-0018） | AI とサーバに向けた操作と、変更の記録の形 |
| 変更の記録 | 画面の「元に戻す」は、ファイルごとにテキストの版を並べて持つ（F-EDIT-4）。誰が変えたかは持たない | 変更に版と書き手を付け、届け直す・取り消す・ほかの変更と合わせる仕組み |

閉じた連携の提案（ADR-0017、#55。提案の中身は `docs/adr-web-integration` のブランチに残っている）は、ほかのウェブアプリへの埋め込みを扱っていた。そこで挙げた論点（入口・出口・契約・問題を返す口・C-2 との両立・AGPL・埋め込みを誰に許すか）は、この ADR で引き取る。

## 決定（案）

### 1. 外に出す操作は「読む・確かめる・意図を渡す・図を書き出す」の 4 つにそろえる

AI（MCP）、開いているアプリ、サーバのどこから使っても、同じ操作を同じ形で使う。

| 操作 | 内容 | 返すもの |
| --- | --- | --- |
| 読む | プロジェクト（フォルダ）のファイル一覧、要素の一覧（種類・修飾名・定義の位置）、要素の中身（属性・関係・説明）、図の一覧 | plugin-sdk の「プラグインに渡すモデル」と同じ形を基にする |
| 確かめる | 問題一覧（構文エラー・参照切れ・まだ扱えない構文・トレースの抜け・チェックルールの結果） | 位置（行・列）と種類と文 |
| 意図を渡す | 画面と同じ編集の意図。要素は **修飾名**（`BicycleLight::Battery`）でも指せるようにする | 作った `TextEdit` と、変えたあとの問題一覧 |
| 図を書き出す | 図の名前（または種類と対象）から、SVG・PNG・draw.io | 図のデータ |

- テキストを丸ごと渡して書き換えることもできる（AI がテキストで書くほうが得意な場面のため）。そのときも、変更は `TextEdit` に直して記録する。
- 意図を外に出すにあたり、図の要素のキーで指す今の形は残し、修飾名で指す形を足す。

### 2. 契約は plugin-sdk に置き、役割を「Modelith とほかのソフトの契約」に広げる

- 操作の入出力と変更の記録の型は、plugin-sdk（MIT）に Rust の型で置き、JSON Schema と TypeScript の型を生成する（今のプラグインの契約と同じ作り）。
- MCP のサーバ、開いているアプリとの通信、共同編集のサーバは、どれもこの契約を使う。外のソフトは MIT の型だけに依存し、本体のコードを組み込まない（ADR-0006）。
- 安定するまでは、契約の版を 0 のままにし、互換を約束しない。

### 3. 図を書き出す処理の置き場所

配置と描画が TypeScript にあるため、次のどれかを選ぶ。

| 方式 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| A. Rust に移す | 配置と SVG の描画をコアに移す | CLI が Rust のまま 1 つの実行ファイルで済む。サーバでも同じものを使える | 大きな移植。画面の描画と二重にならないよう、画面も Rust の結果を使うように変える必要がある |
| B. CLI と MCP を Node で作る | `modelith mcp` を npm のパッケージにし、wasm のコアと、Web アプリの配置・描画の TypeScript をそのまま使う | 移植が要らない。画面と同じ図が確実に出る | 実行に Node が要る。CLI が Rust（`check`）と Node（`mcp`）の 2 つになる |
| C. 書き出しだけ後にする | 0.3.0 の MCP は読む・確かめる・書くだけにし、図の書き出しは A か B を決めてから入れる | 0.3.0 を早く出せる | AI が図を見られない |

**案：B**。AI 向けの MCP は Node で動かすのが一般的で、利用者の負担が小さい。画面と同じ図が出ることを優先する。
`modelith check`（Rust）はそのまま残し、いずれ `modelith mcp` から同じ検査を呼ぶ。A は、サーバで図を作る必要が出たとき（0.5.0 以降）に改めて考える。

### 4. 変更の記録（0.4.0 で作る。形はここで決める）

すべての書き換え（人・AI・ほかの人）を、次の形で記録する。

| 項目 | 内容 |
| --- | --- |
| 対象 | ファイル（プロジェクトの中のパス） |
| 元の版 | 書き換える前のテキストの版（ハッシュか、増えていく番号） |
| 書き換え | `TextEdit` の並び（UTF-16 の位置） |
| 書き手 | 人（この画面）・AI（MCP のクライアントの名前）・ほかの人（0.6.0 以降） |
| 意図 | 画面や AI が渡した意図（あれば。履歴を読みやすくする） |

- 元の版が今の版と違うときは、書き換えを今の版に合わせて直す（位置をずらす）。合わせられないとき（同じ所が変わっていた）は、黙って上書きせずに断り、書き手に知らせる。0.7.0 の同時編集までは、これで足りる。
- 画面の「元に戻す」は、この記録を使うように作り直し、AI の書き換えも戻せるようにする。
- 同時の書き換えを自動で合わせる仕組み（テキストの CRDT か、サーバで順番を決めるか）は、0.7.0 の前にこの ADR を書き足して決める。記録の形は、どちらにも載せられるようにしておく。

### 5. 安全とプライバシー（C-2 との両立）

- MCP は、利用者が自分のパソコンで動かし、利用者が許したフォルダだけを読む・書く。モデルを Modelith の外に送るのは、利用者がつないだ AI のクライアントだけで、Modelith 自身は送らない。
- 開いているアプリとの通信（0.4.0）は、このパソコンの中（`localhost`）だけにする。どのオリジンから受け付けるかを絞る。
- 書く操作は、既定で「差分を見せてから書く」とし、確かめずに書くかは利用者が選ぶ（決めること）。
- サーバに送ることについては、[ADR-0025](0025-server-boundary.md) で C-2 の言葉を書き換える。

### 6. CLI と MCP の配り方

今の CLI（`modelith check`）は、crates.io にも出さず、リリースにも付けていない（`cargo build` で作るしかない）。AI のクライアントから使うには、1 行で入れて動かせる必要がある。

| 方式 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| a. npm のパッケージ | `npx @modelith/cli mcp` のように使う。wasm のコアと、Web アプリの配置・描画の TypeScript を同梱する | Claude Code・Codex の MCP の設定でよく使う形。3 の B と合う | Node が要る |
| b. リリースに実行ファイルを付ける | Rust の `modelith` を OS ごとに作り、GitHub のリリースに付ける | Node が要らない | 図の書き出しは 3 の A が要る。OS ごとの組み立てと署名の手間 |
| c. `cargo install` | crates.io に出す | 手間が少ない | Rust の開発環境が要る。AI を使う一般の利用者向けではない |

**案：a**。`check` も同じパッケージから使えるようにし（wasm のコアで動かす）、Rust の実行ファイル（b）は、サーバと同じ組み立てを作る 0.5.0 で改めて考える。パッケージの版は本体の版とそろえる（versioning.md）。

## 未決（メンテナに決めてもらうこと）

- [ ] 図の書き出しの方式（案：B。Node で動く `modelith mcp`）
- [ ] AI が書く前に人が確かめるか（案：既定は確かめる。設定で外せる）
- [ ] 契約の置き場所（案：plugin-sdk。役割を広げる）
- [ ] ADR-0017（ほかのウェブアプリへの埋め込み）をこの ADR に吸収して閉じるか、埋め込みだけ別に残すか
- [ ] CLI と MCP の配り方（案：a。npm のパッケージ）

## 結果（採用した場合）

- AI・開いているアプリ・サーバが、同じ操作と同じ契約でモデルを扱う。0.4.0 以降の共同編集は、この上に積む。
- 画面の外からの書き換えも、すべて `TextEdit` としてテキストに入り、記録に残る（ADR-0001 を保つ）。
- CLI は npm のパッケージとして配り、`check` と `mcp` を同じ形で使える（3 の B と 6 の a を選んだ場合）。Rust の `modelith check` は開発と CI のために残す。
