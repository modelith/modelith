# ADR-0025: サーバの境目（何をサーバに置き、何を手元に残すか）

- 状態: 提案
- 日付: 2026-11-12
- 関連する ADR: ADR-0001（テキストが唯一の正本）、ADR-0003（ウェブアプリを本体とする）、ADR-0006（ライセンス）、ADR-0012（クラウド保存）、ADR-0019（プロジェクト）、ADR-0023（版をまたいでファイルを壊さない）、ADR-0024（AI と共同編集の土台）、ADR-0026（利用状況の送信）

## 背景

0.5.0 から、プロジェクトをサーバに置いて、どのパソコンからも開けるようにする。0.6.0 でほかの人に見せ、0.7.0 で同時に編集する（[リリース計画（0.3.0 から先）](../development/release-plan-0.3.0.md)）。
サーバは、誰でも自分の環境で動かせるようにする（セルフホスティング）。

今の Modelith は、サーバを持たない前提で作っている。

- C-2：モデルや操作の情報を、利用者が選んだ保存先（手元のファイル、利用者自身のクラウドストレージ）以外に送らない。
- C-4：サーバを持たない静的なファイルとして配信でき、誰でも自分の環境に置ける。
- 保存先は「プロバイダ」（ブラウザ・ダウンロード・手元のフォルダ）として差し替えられる（ADR-0019）。

サーバを足すにあたって、手元だけで使う人の体験を変えず、サーバを使う人には、どこに何を送るかがはっきり分かる形にする必要がある。

## 決定（案）

### 1. サーバは「もう 1 つの保存先」として足す

- アプリは今までどおり静的なファイルとして配り、サーバが無くても全部の機能が使える（C-4 を守る）。
- サーバは、手元のフォルダと同じく、プロジェクトを開いて保存する保存先の 1 つ（プロバイダ）として足す。利用者がサーバにつないだときだけ、そのサーバと通信する。
- C-2 の「利用者が選んだ保存先」に、「利用者が選んだ Modelith のサーバ」を足す。それ以外には送らない（利用状況の送信は ADR-0026 で別に決める）。

### 2. サーバに置くのはテキストと配置ファイル。解析はどちらでもコアが行う

- サーバが持つのは、プロジェクトのファイル（`.sysml`・`.kerml`・`.layout.json`・`modelith.json`）と、変更の記録（ADR-0024 の 4）だけ。テキストが正本であることは変わらない（ADR-0001）。
- 解析・検査・図の操作は、アプリでもサーバでも同じ Rust のコアで行う。サーバ専用の解釈を作らない。
- サーバは Rust で作り、コアを直接使う（`modelith-server`。このリポジトリに置き、AGPL-3.0）。

### 3. サーバの外とつなぐ口を、決まった形で用意する

サーバを動かす人ごとに違うものは、サーバの本体に書かず、決まった口から差し込めるようにする。

| 口 | 内容 | 本体に入れる既定のもの |
| --- | --- | --- |
| 認証 | 誰がログインしているかを確かめる | 管理者が作るアカウントと合言葉（0.5.0）。OIDC（0.6.0 以降） |
| 保存 | プロジェクトのファイルと記録をどこに置くか | サーバのディスク上のフォルダ |
| 利用者と役割 | 誰がどのプロジェクトで何をできるか | プロジェクトごとの役割（持ち主・編集・閲覧） |

- 口は、サーバの中のインターフェイスと、プロセスの外から使う API の両方で定める。本体の外の仕組み（別のログインの仕組みや保存先）をつなぐときは、API の境目越しにつなぎ、本体のコードを組み込まない（ADR-0006 の 4 と同じ考え方）。
- サーバとアプリの通信の形（プロジェクトの一覧・開く・保存する・変更を受け取る）は、ADR-0024 の契約（plugin-sdk）に置く。

### 4. プロジェクトの一覧とタブ

- サーバにつないだら、そのサーバのプロジェクトの一覧を出し、選んで開く（0.5.0）。
- ブラウザのタブごとに、別のプロジェクトを開ける。タブの間で、開いているプロジェクトの状態を共有しない（下書きは ADR-0023 と同じく、ほかのタブの分を消さない）。

### 5. 版の違い

- サーバとアプリの版が違っても、ファイルを壊さない（ADR-0023 と同じく、知らない項目を残し、読めない形は書き換えない）。
- 通信の形には版を付け、サーバが知らない版のアプリには、つなげない理由を示す。

## 未決（メンテナに決めてもらうこと）

- [ ] サーバの通信の方式（案：開く・保存は HTTP、変更を受け取るのは WebSocket）
- [ ] 0.5.0 のログイン（案：管理者が作るアカウントと合言葉。OIDC は 0.6.0）
- [ ] サーバの保存の既定（案：ディスク上のフォルダ。データベースは使わない。変更の記録だけを別のファイルに足していく）
- [ ] C-2 と C-4 の書き換えの文（下の「結果」の形でよいか）

## 結果（採用した場合）

- 要求 C-2 を、次のように書き換える：「利用者のモデルや操作の情報を、利用者が選んだ保存先（手元のファイル、利用者自身のクラウドストレージ、利用者が選んだ Modelith のサーバ）以外に送らない。利用状況の送信は ADR-0026 に従う」。
- 要求 C-4 は変えない（サーバは任意の追加）。
- サーバの要求（F-SRV-…）を、0.5.0 の前に要求仕様に足す。
- サーバを動かす人は、本体の AGPL のサーバをそのまま使うか、決まった口から自分の仕組みをつなぐ。
