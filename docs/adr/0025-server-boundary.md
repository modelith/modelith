# ADR-0025: サーバの境目（何をサーバに置き、何を手元に残すか）

- 状態: 採用（2026-11-12）
- 日付: 2026-11-12
- 関連する ADR: ADR-0001（テキストが唯一の正本）、ADR-0003（ウェブアプリを本体とする）、ADR-0006（ライセンス）、ADR-0012（クラウド保存）、ADR-0019（プロジェクト）、ADR-0023（版をまたいでファイルを壊さない）、ADR-0024（AI と共同編集の土台）、ADR-0026（利用状況の送信）

## 背景

0.5.0 から、プロジェクトをサーバに置いて、どのパソコンからも開けるようにする。0.6.0 でほかの人に見せ、0.7.0 で同時に編集する（[リリース計画（0.3.0 から先）](../development/release-plan-0.3.0.md)）。
サーバは、誰でも自分の環境で動かせるようにする（セルフホスティング）。

今の Modelith は、サーバを持たない前提で作っている。

- C-2：モデルや操作の情報を、利用者が選んだ保存先（手元のファイル、利用者自身のクラウドストレージ）以外に送らない。
- C-4：サーバを持たない静的なファイルとして配信でき、誰でも自分の環境に置ける。
- 保存先は「プロバイダ」（ブラウザ・ダウンロード・手元のフォルダ）として差し替えられる（ADR-0019）。

サーバを足すにあたって、手元だけで使う人の体験を変えず、サーバを使う人には、どこに何を送るかがはっきり分かる形にする必要がある。

## 決定

### 1. サーバは「もう 1 つの保存先」として足す

- アプリは今までどおり静的なファイルとして配り、サーバが無くても全部の機能が使える（C-4 を守る）。
- サーバは、手元のフォルダと同じく、プロジェクトを開いて保存する保存先の 1 つ（プロバイダ）として足す。利用者がサーバにつないだときだけ、そのサーバと通信する。
- C-2 の「利用者が選んだ保存先」に、「利用者が選んだ Modelith のサーバ」を足す。それ以外には送らない（利用状況の送信は ADR-0026 で別に決める）。

### 2. サーバに置くのはテキストと配置ファイル。解析はどちらでもコアが行う

- サーバが持つのは、プロジェクトのファイル（`.sysml`・`.kerml`・`.layout.json`・`modelith.json`）と、変更の記録（ADR-0024 の 4）だけ。テキストが正本であることは変わらない（ADR-0001）。
- 解析・検査・図の操作は、アプリでもサーバでも同じ Rust のコアで行う。サーバ専用の解釈を作らない。
- サーバは Rust で作り、コアを直接使う（`modelith-server`。このリポジトリに置き、AGPL-3.0）。

### 3. サーバの外とつなぐ口を、決まった形で用意する

サーバを動かす人ごとに違うものは、サーバの本体に書かず、決まった口から差し込めるようにする。

| 口 | 内容 | 本体に入れる既定のもの |
| --- | --- | --- |
| 認証 | 誰がログインしているかを確かめる | 管理者が作るアカウントと OIDC の両方（0.5.0 から。下の 6） |
| 保存 | プロジェクトのファイルと記録をどこに置くか | テキストはディスク上のフォルダ、それ以外は SQLite（下の 7） |
| 利用者と役割 | 誰がどのプロジェクトで何をできるか | プロジェクトごとの役割（持ち主・編集・閲覧） |

- 口は、サーバの中のインターフェイスと、プロセスの外から使う API の両方で定める。本体の外の仕組み（別のログインの仕組みや保存先）をつなぐときは、API の境目越しにつなぎ、本体のコードを組み込まない（ADR-0006 の 4 と同じ考え方）。
- サーバとアプリの通信の形（プロジェクトの一覧・開く・保存する・変更を受け取る）は、ADR-0024 の契約（plugin-sdk）に置く。

### 4. プロジェクトの一覧とタブ

- サーバにつないだら、そのサーバのプロジェクトの一覧を出し、選んで開く（0.5.0）。
- ブラウザのタブごとに、別のプロジェクトを開ける。タブの間で、開いているプロジェクトの状態を共有しない（下書きは ADR-0023 と同じく、ほかのタブの分を消さない）。

### 5. 版の違い

- サーバとアプリの版が違っても、ファイルを壊さない（ADR-0023 と同じく、知らない項目を残し、読めない形は書き換えない）。
- 通信の形には版を付け、サーバが知らない版のアプリには、つなげない理由を示す。

### 6. 通信とログイン

- 開く・保存は HTTP、変更を受け取るのは WebSocket。どちらも既定で暗号化する（HTTPS・WSS）。
- サーバは、アプリ（静的なファイル。C-4）も同梱して同じ場所から配る。アプリとサーバが同じ場所にあるので、外のネットワークに出られない環境でも使える。
- 証明書は、次のどれでも使えるようにする：前に置くサーバ（Caddy・nginx など）に任せる、社内の認証局の証明書、サーバが作る自己署名の証明書、暗号化しない HTTP（画面に「通信が暗号化されていない」と示す）。
- ログインは、0.5.0 から管理者が作るアカウントと OIDC の両方を使える。管理者が作るアカウントは、次のように守る。

| 項目 | 決めたこと |
| --- | --- |
| 最初の管理者 | 既定の合言葉は作らない。初めて起動したとき、1 回だけ使える設定用のリンクをサーバの記録に出す |
| 合言葉 | Argon2id でハッシュにして保存する。短い合言葉・よく漏れている合言葉は断る |
| 総当たり | 失敗が続いたら待ち時間を延ばし、一時的に止める |
| 2 段階の確認 | 認証アプリ（TOTP）。管理者には必須にできる |
| ログインの状態 | Cookie（HttpOnly・Secure・SameSite）に期限を付ける。CSRF を防ぐ |
| 招待 | 期限付きで 1 回だけ使えるリンク。メールが無くても使える |
| 合言葉を忘れたとき | 管理者が作り直す（メールでの再設定は作らない） |
| OIDC と並べるとき | OIDC を有効にしたら、合言葉でのログインを非常用の管理者だけに絞れる |
| 記録 | ログインの成功・失敗と、権限の変更を監査の記録に残す |

### 7. 保存

- モデルのテキストと配置ファイルは、サーバのディスク上のフォルダにファイルのまま置く。
- 利用者・ログインの状態・招待・プロジェクトと役割・変更の記録・監査の記録・サーバの利用状況の集計は、SQLite に置く。関係のあるデータを制約で守り、変更の記録を順に確実に書くため、RDB にする。
- 保存の口（3）を通して、複数台で動かすときに PostgreSQL へ移せるようにする。

### 8. 外へ出る通信の一覧

Grafana と同じく、アプリとサーバが外へ出る通信を種類ごとに一覧にして、マニュアルに載せ、1 つずつ止められるようにする。止めても、ほかの機能は壊れない。

| 通信 | 送り先 | 止め方 |
| --- | --- | --- |
| 利用者が選んだサーバとの通信 | 利用者が選んだ Modelith のサーバ | つながない |
| 利用状況の送信 | Modelith の受け口（ADR-0026） | 設定・環境変数・`DO_NOT_TRACK` |
| エラーの送信 | Modelith の受け口（ADR-0026） | 同上 |
| プラグインの登録簿の取得 | plugin-registry | 設定 |

新しい通信を足すときは、この一覧に足し、止め方を用意する。

## 決めたこと（メンテナの判断、2026-11-12）

- 通信は HTTP と WebSocket。既定で HTTPS・WSS。外に出られない環境のため、アプリを同梱し、社内の証明書・自己署名・HTTP も使えるようにする
- ログインは、管理者が作るアカウントと OIDC の両方を 0.5.0 から。守り方は 6 の表
- 保存は、テキストはファイル、それ以外は SQLite。PostgreSQL へ移せる作り
- C-2 は下の「結果」の文に書き換え、外へ出る通信の一覧（8）を作る

## 結果

- 要求 C-2 を、次のように書き換える：「利用者のモデルや操作の情報を、利用者が選んだ保存先（手元のファイル、利用者自身のクラウドストレージ、利用者が選んだ Modelith のサーバ）以外に送らない。フォントなども同梱し、外部の CDN やアクセス解析を使わない。外へ出る通信は、マニュアルの一覧に載せたものだけにし、どれも止められる（利用状況とエラーの送信は ADR-0026 に従う）」。
- 要求 C-4 は変えない（サーバは任意の追加）。
- サーバの要求（F-SRV-…）を、0.5.0 の前に要求仕様に足す。
- サーバを動かす人は、本体の AGPL のサーバをそのまま使うか、決まった口から自分の仕組みをつなぐ。
