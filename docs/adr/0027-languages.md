# ADR-0027: 画面と文書の言語（英語と日本語、その先の多言語）

- 状態: 提案
- 日付: 2026-11-13
- 関連する ADR: ADR-0008（原則をハーネスで強制する）、ADR-0014（画面の言葉）、ADR-0016（Rust のモデルと Worker）、ADR-0022（3 つの系列）、ADR-0024（AI と共同編集の土台）、ADR-0026（利用状況の送信）

## 背景

Modelith の画面と文書は、日本語だけで書いてきた。SysML v2 を使う人の多くは日本の外にいて、英語の画面と文書が無いと試してもらえない。
メンテナは、英語と日本語に対応し、いずれはほかの言語にも広げたいと考えている（2026-11-13）。

今の文言の置き場所は次のとおり（テストとコメントを除いた、日本語を含む行の数）。

| 置き場所 | 量 | 例 |
| --- | --- | --- |
| Web アプリの TypeScript（`web/src`） | 約 110 ファイル・約 1,000 行 | トースト・ダイアログ・ツールチップ・メニュー |
| `web/index.html` | 約 100 行 | 画面の骨組みのボタン・見出し |
| Rust のコア（`crates/*/src`） | 約 700 行 | 問題一覧の文（構文エラー・参照切れ・トレースの抜け）、設定ファイルのエラー |

文書は、利用者向け（マニュアルのサイト・README・CONTRIBUTING・SECURITY・リリースノート）と、開発者向け（ADR・要求仕様・開発の手順・対応表）に分かれる。
README・CONTRIBUTING・SECURITY は、2026-11-13 に英語を主にし、日本語のページを並べた（plugin-sdk と同じ形）。

### ほかの OSS のやり方

多言語の対応が利用者・翻訳者に好評な OSS は、次のようにしている（2026-11 に各プロジェクトの公開の文書で確かめた）。

| 製品 | 元の言語 | 辞書の形 | 翻訳の場 | そのほか |
| --- | --- | --- | --- | --- |
| VS Code（拡張機能） | 英語 | 言語ごとの JSON（`bundle.l10n.json` を元に `bundle.l10n.<言語>.json`） | 言語パック、XLIFF で翻訳者とやり取り | 疑似翻訳（文字を変えて伸ばした言語）を作り、訳し忘れと幅のあふれを見つける |
| Grafana | 英語（リポジトリが正本） | i18next の JSON。複数形はキーを分ける | Crowdin（訳はそちらが正本。GitHub Actions で取り込む） | ESLint の規則で、辞書を通さない文を止める。プラグインにも同じ仕組みを渡す |
| Home Assistant | 英語（`strings.json`） | JSON。値の差し込みは ICU MessageFormat（formatjs） | Lokalise（マージ後に自動で上げ、定期的に取り込む） | 連携ごとに辞書を持つ |
| Penpot | 英語（`en.po`） | gettext の PO | Weblate（ホスト版） | 訳す人を限っている |
| Excalidraw | 英語 | 言語ごとの JSON | Crowdin | 訳の進み具合を自動で計り、85% に満たない言語を選択肢に出さない |
| Firefox | 英語 | Fluent（FTL。Rust の実装 fluent-rs） | Pontoon（自前） | 性・数・活用まで訳者が書ける |
| Kubernetes・OpenTelemetry の文書 | 英語 | Markdown（言語ごとのフォルダ） | GitHub の PR（言語ごとの担当者が承認） | 英語を既定に、ほかの言語を `/ja/` などのパスに置く |

共通しているのは次の点である。

- **元の言語は英語**にし、ほかの言語はその訳にする。翻訳者は英語から訳すことが多い。
- 辞書は**言語ごとの平らなファイル**（JSON か PO）で、翻訳のサービスがそのまま読める形にする。
- **辞書を通さない文を、機械的な検査で止める**（Grafana の ESLint の規則）。
- 訳が足りない言語は、**元の言語の文を出す**。進んでいない言語は選択肢に出さない（Excalidraw）。
- 翻訳は、**翻訳のサービス**（Crowdin・Weblate・Lokalise）でコミュニティから受け付ける。Weblate のホスト版は、公開のリポジトリで OSI の認めたライセンスのプロジェクトには無料で使える（libre プラン）。

## 決定

### 1. 進め方

| 版 | すること |
| --- | --- |
| 0.3.0 | **土台**。この ADR を採用し、文言を言語ごとの辞書に移す仕組みを作り、今の文言を移す。画面は日本語のまま |
| 0.4.0 | **英語版**。英語の辞書を入れ、言語を選べるようにする。マニュアルの英語版を、安定版のページから作る |
| その先 | ほかの言語。翻訳のサービスでコミュニティから受け付ける |

文書は、利用者向けを先に英語と日本語の両方にし、それが終わってから開発者向けに広げる（メンテナの判断、2026-11-13）。

### 2. 辞書（文言の置き場所）

- 文言は、言語ごとの辞書ファイルに、キーと文で置く（例：`web/src/locales/en.json` の `"export.done": "Exported \"{name}\""`、`ja.json` の `"export.done": "「{name}」をエクスポートしました"`）。コードには文を書かず、キーと値を渡す。
- 形は **i18next の JSON**（平らなキー、値の差し込みは `{name}`、複数形はキーを分ける：`files_one`・`files_other`）にそろえる。Grafana と同じ形で、Crowdin・Weblate・Lokalise がそのまま読める。
  - 読むのは自分たちの小さな関数にし、i18next などの npm の依存は足さない。複数形の選び分けは、ブラウザと Node が持つ `Intl.PluralRules` を使う。
  - ICU MessageFormat（Home Assistant）や Fluent（Firefox）は、言い回しをより細かく書けるが、TypeScript 側に解析のライブラリが要る。今の文言（差し込みと数）には要らないので使わない。性・活用を訳し分ける言語を足すときに、改めて考える。
- **元の言語は英語**にする（0.4.0 から）。キーが無い言語では英語の文を出す。0.3.0 の間は英語の辞書がまだ無いので、日本語の文を出す。
- 日本語の辞書は、メンテナがリポジトリの中で直接書く（ADR-0014 の言葉の手引きに従うため）。英語と日本語のほかの言語は、翻訳のサービスを正本にし、自動で取り込む（Grafana と同じ）。

### 3. コアの文（問題一覧など）

問題一覧の文は、コア（Rust）が作り、ブラウザ・CLI（`modelith check`）・MCP が同じ文を出す（ADR-0024）。

- コアの問題は、今の `msg`（文）に加えて、**キーと値**を持つようにする。文はコアが辞書から作る（コアの辞書は crate の中に置き、ビルドで組み込む）。形は 2 と同じ i18next の JSON で、翻訳のサービスでは画面の辞書と並べて扱う。
- 言語は、呼ぶ側（画面・CLI の引数・MCP の設定）がコアに渡す。コアは端末の設定を読まない。
- 問題の種類のコード（`trace.derive` など。F-EDIT-11）は、言語によらず同じにする。AI と検査ルールは、文ではなくコードで判断できる。

### 4. 言語の選び方（利用者の環境に合わせ、利用者が変えられる）

既定は、利用者の環境の言語に合わせて自動で選ぶ。利用者が選び直したら、それを優先する（メンテナの判断、2026-11-13）。

| 場所 | 自動で選ぶもと | 利用者が変える方法 | 選んだものの置き場所 |
| --- | --- | --- | --- |
| Web アプリ | ブラウザの言語の設定（`navigator.languages`。OS の言語の設定がブラウザに引き継がれる）。並んだ順に見て、辞書のある最初の言語にし、無ければ英語 | 「設定」の「言語」で、「自動（ブラウザに合わせる）」か、言語を 1 つ選ぶ。既定は「自動」 | このブラウザの設定（プロジェクトの設定には置かない。同じプロジェクトを違う言語の人が開くため） |
| マニュアルのサイト | 初めて `/` を開いたとき、ブラウザの言語が日本語なら `/ja/` へ案内する | 画面の上の言語の切り替え。切り替えたら、次からは自動で移さない | このブラウザの設定 |
| CLI・MCP | 環境変数（`LC_ALL`・`LC_MESSAGES`・`LANG` の順。OS の言語の設定） | 引数（`--lang`）か、MCP の設定 | 呼ぶ側の設定 |

- 「自動」のときは、ブラウザの言語の設定を変えれば、次に開いたときから変わる。言語を選んだときは、ブラウザの設定が変わっても、選んだ言語のままにする（VS Code・GitHub と同じ）。
- 選択肢には、訳の進み具合が決めた割合以上の言語だけを出す（Excalidraw は 85%）。割合は辞書を取り込むときに計る。英語と日本語は、常に 100% にする。選んだ言語が割合を下回ったら、「自動」に戻して知らせる。
- 言語は画面の文言だけを変える。モデルのテキスト・要素の名前・ファイル名は変えない。
- 送る利用状況の「表示の言語」（ADR-0026 の 5）は、実際に表示している言語を送る。

### 5. 言葉の手引き

- 画面の言葉の手引き（ADR-0014）は、どの言語にも当てはめる。図の言葉を先に、SysML v2 の用語は補足に回す。
- 英語の手引きを、日本語の手引きの隣に置く。英語では、SysML v2 の英語の用語（part・requirement など）が一般の言葉と重なるので、どこまで言い換えるかを英語の手引きで決める。
- 図に描く記号（`«part def»` などのステレオタイプ）は、言語によらずそのまま描く。

### 6. ハーネス（ADR-0008）

- 移し終えたフォルダから順に、コードに文が直接書かれていないことを検査する（Grafana の ESLint の規則に当たるものを、`scripts/check.sh` の検査として作る。コメントとテストを除く）。
- 言語ごとの辞書のキーがそろっていること、差し込む値の名前が言語の間で同じことを検査する。
- **疑似翻訳**の言語（VS Code と同じく、文字を変えて 3 割ほど伸ばしたもの）を辞書から自動で作り、UI テストで、訳し忘れ（元の文のまま出ている所）と、幅のあふれを見つける。
- e2e と UI テストの基準画像は、日本語のまま撮る。英語の画面は、言語を切り替える主な流れだけを確かめる。

### 7. 文書

| 文書 | 英語と日本語 | 置き方 |
| --- | --- | --- |
| README・CONTRIBUTING・SECURITY | 済み（2026-11-13） | 英語を `*.md`、日本語を `*.ja.md` |
| マニュアルのサイト | 0.4.0 から | VitePress の言語の切り替え（`locales`）。Kubernetes・OpenTelemetry・VitePress 自身の文書と同じく、**英語を `/`、日本語を `/ja/`** に置く。今の日本語のページのパスには、`/ja/` の同じページへ移す案内のページを残す。言語の自動の選び方は 4 のとおり。版のフォルダ（安定版・プレビュー版）ごとに両方の言語を持つ |
| リリースノート | 0.4.0 から | 英語と日本語を 1 つのリリースに並べる（GitHub のリリースは 1 つしか本文を持てないため）。書き方は release のスキルで決める |
| 例のモデル・サンプル | 0.4.0 から | 英語の画面では、英語の名前のサンプルを開く（自分で作る。モックのサンプルは使わない） |
| 開発者向け（ADR・要求仕様・開発の手順・対応表） | 利用者向けが終わってから | 置き方は、そのときに決める |

### 8. 翻訳を受け付ける場（その先）

ほかの言語を足すときは、**Weblate のホスト版（libre プラン）**を第一の案にする。Weblate 自身がオープンソース（GPL）で、無料で使え、Penpot などのデザインツールが使っている。Crowdin（Grafana・Excalidraw）も OSS には無料だが、サービスそのものは非公開である。どちらも i18next の JSON を読めるので、2 の形は変えずに済む。決めるのは、ほかの言語を受け付けると決めたときにする。

## 決めること（採用の前に）

- 辞書の形：i18next の JSON を自分たちの小さな関数で読む（推奨）か、ICU MessageFormat か、Fluent か
- 元の言語：英語（推奨。ほかの OSS と同じで、翻訳者が訳しやすい）か、日本語のままか
- コアの文：コアが辞書から文を作る（推奨）か、コアはキーと値だけを返し、画面・CLI・MCP がそれぞれ文にするか
- マニュアルのパス：英語を `/`、日本語を `/ja/`（推奨。ほかの OSS と同じ。今のリンクには案内のページを残す）か、日本語を `/` のまま英語を `/en/` に置くか
- 英語の画面で、SysML v2 の用語をどこまで言い換えるか（英語の手引きで決める）

## 結果

- 0.3.0 のあと、文言を足すときは辞書に書く。コードに文を直接書くと、検査で止まる。
- 0.4.0 で、英語の画面とマニュアルを出せる。ほかの言語は、辞書を足すだけで加えられる。
- 要求仕様に、言語の要求（画面の言語を選べる・問題一覧の文が選んだ言語で出る・CLI と MCP の言語）を足す（採用のとき）。
