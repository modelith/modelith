# ADR-0027: 画面と文書の言語（英語と日本語、その先の多言語）

- 状態: 採用（2026-11-14。同日改訂：辞書の形を Fluent に）
- 日付: 2026-11-13
- 関連する ADR: ADR-0008（原則をハーネスで強制する）、ADR-0014（画面の言葉）、ADR-0016（Rust のモデルと Worker）、ADR-0022（3 つの系列）、ADR-0024（AI と共同編集の土台）、ADR-0026（利用状況の送信）

## 背景

Modelith の画面と文書は、日本語だけで書いてきた。SysML v2 を使う人の多くは日本の外にいて、英語の画面と文書が無いと試してもらえない。
メンテナは、英語と日本語に対応し、いずれはほかの言語にも広げたいと考えている（2026-11-13）。

今の文言の置き場所は次のとおり（テストとコメントを除いた、日本語を含む行の数）。

| 置き場所 | 量 | 例 |
| --- | --- | --- |
| Web アプリの TypeScript（`web/src`） | 約 110 ファイル・約 1,000 行 | トースト・ダイアログ・ツールチップ・メニュー |
| `web/index.html` | 約 100 行 | 画面の骨組みのボタン・見出し |
| Rust のコア（`crates/*/src`） | 約 700 行 | 問題一覧の文（構文エラー・参照切れ・トレースの抜け）、設定ファイルのエラー |

文書は、利用者向け（マニュアルのサイト・README・CONTRIBUTING・SECURITY・リリースノート）と、開発者向け（ADR・要求仕様・開発の手順・対応表）に分かれる。
README・CONTRIBUTING・SECURITY は、2026-11-13 に英語を主にし、日本語のページを並べた（plugin-sdk と同じ形）。

### ほかの OSS のやり方

多言語の対応が利用者・翻訳者に好評な OSS は、次のようにしている（2026-11 に各プロジェクトの公開の文書で確かめた）。

| 製品 | 元の言語 | 辞書の形 | 翻訳の場 | そのほか |
| --- | --- | --- | --- | --- |
| VS Code（拡張機能） | 英語 | 言語ごとの JSON（`bundle.l10n.json` を元に `bundle.l10n.<言語>.json`） | 言語パック、XLIFF で翻訳者とやり取り | 疑似翻訳（文字を変えて伸ばした言語）を作り、訳し忘れと幅のあふれを見つける |
| Grafana | 英語（リポジトリが正本） | i18next の JSON。複数形はキーを分ける | Crowdin（訳はそちらが正本。GitHub Actions で取り込む） | ESLint の規則で、辞書を通さない文を止める。プラグインにも同じ仕組みを渡す |
| Home Assistant | 英語（`strings.json`） | JSON。値の差し込みは ICU MessageFormat（formatjs） | Lokalise（マージ後に自動で上げ、定期的に取り込む） | 連携ごとに辞書を持つ |
| Penpot | 英語（`en.po`） | gettext の PO | Weblate（ホスト版） | 訳す人を限っている |
| Excalidraw | 英語 | 言語ごとの JSON | Crowdin | 訳の進み具合を自動で計り、85% に満たない言語を選択肢に出さない |
| Firefox | 英語 | Fluent（FTL。Rust の実装 fluent-rs） | Pontoon（自前） | 性・数・活用まで訳者が書ける |
| Kubernetes・OpenTelemetry の文書 | 英語 | Markdown（言語ごとのフォルダ） | GitHub の PR（言語ごとの担当者が承認） | 英語を既定に、ほかの言語を `/ja/` などのパスに置く |

共通しているのは次の点である。

- **元の言語は英語**にし、ほかの言語はその訳にする。翻訳者は英語から訳すことが多い。
- 辞書は**言語ごとの平らなファイル**（JSON か PO）で、翻訳のサービスがそのまま読める形にする。
- **辞書を通さない文を、機械的な検査で止める**（Grafana の ESLint の規則）。
- 訳が足りない言語は、**元の言語の文を出す**。進んでいない言語は選択肢に出さない（Excalidraw）。
- 翻訳は、**翻訳のサービス**（Crowdin・Weblate・Lokalise）でコミュニティから受け付ける。Weblate のホスト版は、公開のリポジトリで OSI の認めたライセンスのプロジェクトには無料で使える（libre プラン）。

## 決定

### 1. 進め方

| 版 | すること |
| --- | --- |
| 0.3.0 | **土台**。この ADR を採用し、文言を言語ごとの辞書に移す仕組みを作り、今の文言を移す。画面は日本語のまま |
| 0.4.0 | **英語版**。英語の辞書を入れ、言語を選べるようにする。マニュアルの英語版を、安定版のページから作る |
| その先 | ほかの言語。翻訳のサービスでコミュニティから受け付ける |

文書は、利用者向けを先に英語と日本語の両方にし、それが終わってから開発者向けに広げる（メンテナの判断、2026-11-13）。

### 2. 辞書（文言の置き場所）

- 文言は、言語ごとの辞書ファイルに、キーと文で置く。コードには文を書かず、キーと値を渡す。
- 形は **Fluent**（`.ftl`。Firefox と同じ）にする。読むのは、同じプロジェクトの公式の実装（Rust は `fluent-bundle`、TypeScript は `@fluent/bundle`）にし、文にする処理を自分たちで書かない（メンテナの判断、2026-11-14。経緯は下の「改訂」）。

  ```
  # web/src/locales/en/app.ftl
  export-done = Exported "{ $name }"
  files-opened = { $count ->
      [one] Opened { $count } file
     *[other] Opened { $count } files
  }
  # web/src/locales/ja/app.ftl
  export-done = 「{ $name }」をエクスポートしました
  files-opened = { $count } 個のファイルを開きました
  ```

- 辞書は、言語ごとのフォルダに、文を使う場所（`web/src` の下のフォルダ）ごとのファイルで置く（`web/src/locales/<言語>/<場所>.ftl`）。キーは、ファイルの名前で始める。
  図を書き出す `cli` が、図に描く文の辞書だけを読めるようにするため（2026-11-26）。
- 使い方の決まり（辞書の形を替えることになっても、影響を辞書と文にする層の中に閉じるため）：
  - 文言は `t(キー, 値)` の口だけを通して使う。コードは Fluent の型や辞書の形を直接知らない。
  - キーは小文字の英字・数字・`-` だけ、値の名前は英字と数字だけにする。
  - 値の前後に入る見えない記号（文字の向きを区切る U+2068・U+2069）は、入れない設定にする（`useIsolating: false`）。幅は変えないが、コピーした文・入力欄・文字の検索に残るため。右から左に書く言語を足すときに、入れる設定に戻すかを決める。
  - 数は、複数形の選び分けにだけ数として渡す。文に出す数は、呼ぶ側で文字列にしてから渡す。Rust と TypeScript の実装で、数の書き方が違うため（`1234567` と `1,234,567`）。
  - 文に `{`・`}` を書くときは `{"{"}`・`{"}"}` と書く（SysML の `{ … }` を説明する文）。
  - 訳した文は、HTML としてではなく文字として画面に入れる（訳は外から届くので、タグを書かれても動かさない）。
- **元の言語は英語**にする（0.4.0 から）。キーが無い言語では英語の文を出す。0.3.0 の間は英語の辞書がまだ無いので、日本語の文を出す。
- 日本語の辞書は、メンテナがリポジトリの中で直接書く（ADR-0014 の言葉の手引きに従うため）。英語と日本語のほかの言語は、翻訳のサービスを正本にし、自動で取り込む（Grafana と同じ）。

### 3. 問題一覧の文：コアは言語を知らず、文言の層が文にする

問題一覧（構文エラー・参照切れ・トレースの抜けなど）と設定ファイルのエラーは、コア（Rust）が見つけ、ブラウザ・CLI（`modelith check`）・MCP が同じ文で出す（ADR-0024）。
言語に合わせて文を作るのは表示の仕事なので、クリーンアーキテクチャに倣い、内側のコアには持たせない（メンテナの判断、2026-11-14）。

| 層 | crate・場所 | 役割 | 言語を知るか |
| --- | --- | --- | --- |
| コア | `crates/modelith-core` | 問題を、**種類のコードと値**（例：`ref.missing` と `{ name: "X" }`）で返す | 知らない |
| 文言の層 | `crates/modelith-messages`（新規） | 問題のコードと値を、言語ごとの辞書で文にする | 知る |
| 入口 | `crates/modelith-wasm`（画面・MCP）・`crates/modelith-cli` | 言語を決め、コアの結果を文言の層で文にして出す | 選ぶだけ |

- 依存の向きは「入口 → 文言の層 → コア」だけにする。コアは文言の層にも辞書にも依存しない。
- コアのテストは、文ではなくコードと値で確かめる。言い回しを変えても、コアのテストは変わらない（ADR-0014 で、ゴールデンは文言を比べないと決めたのと同じ考え方）。
- 問題一覧の辞書は `modelith-messages` の 1 か所に置く。形は 2 と同じ Fluent で、翻訳のサービスでは画面の辞書と並べて扱う。画面（wasm 経由）・CLI・MCP（wasm のコアを使う）は、どれも同じ文を出す。
- 問題の種類のコード（`trace.derive` など。F-EDIT-11）と値は、言語によらず同じにし、wasm と CLI の出力にも含める。AI・検査ルール・プラグインは、文ではなくコードで判断できる。
- 画面のボタン・トースト・ダイアログなど、Web アプリだけの文言は、2 の TypeScript の辞書に置く。

### 4. 言語の選び方（利用者の環境に合わせ、利用者が変えられる）

既定は、利用者の環境の言語に合わせて自動で選ぶ。利用者が選び直したら、それを優先する（メンテナの判断、2026-11-13）。

| 場所 | 自動で選ぶもと | 利用者が変える方法 | 選んだものの置き場所 |
| --- | --- | --- | --- |
| Web アプリ | ブラウザの言語の設定（`navigator.languages`。OS の言語の設定がブラウザに引き継がれる）。並んだ順に見て、辞書のある最初の言語にし、無ければ英語 | 「設定」の「言語」で、「自動（ブラウザに合わせる）」か、言語を 1 つ選ぶ。既定は「自動」 | このブラウザの設定（プロジェクトの設定には置かない。同じプロジェクトを違う言語の人が開くため） |
| マニュアルのサイト | 初めて `/` を開いたとき、ブラウザの言語が日本語なら `/ja/` へ案内する | 画面の上の言語の切り替え。切り替えたら、次からは自動で移さない | このブラウザの設定 |
| CLI・MCP | 環境変数（`LC_ALL`・`LC_MESSAGES`・`LANG` の順。OS の言語の設定） | 引数（`--lang`）か、MCP の設定 | 呼ぶ側の設定 |

- 「自動」のときは、ブラウザの言語の設定を変えれば、次に開いたときから変わる。言語を選んだときは、ブラウザの設定が変わっても、選んだ言語のままにする（VS Code・GitHub と同じ）。
- 選択肢には、訳の進み具合が決めた割合以上の言語だけを出す（Excalidraw は 85%）。割合は辞書を取り込むときに計る。英語と日本語は、常に 100% にする。選んだ言語が割合を下回ったら、「自動」に戻して知らせる。
- 言語は画面の文言だけを変える。モデルのテキスト・要素の名前・ファイル名は変えない。
- 送る利用状況の「表示の言語」（ADR-0026 の 5）は、実際に表示している言語を送る。

### 5. 言葉の手引き

- 画面の言葉の手引き（ADR-0014）は、どの言語にも当てはめる。図の言葉を先に、SysML v2 の用語は補足に回す。
- 英語の手引きを、日本語の手引きの隣に置く。英語では、SysML v2 の英語の用語（part・requirement など）が一般の言葉と重なるので、どこまで言い換えるかを英語の手引きで決める。
- 図に描く記号（`«part def»` などのステレオタイプ）は、言語によらずそのまま描く。

### 6. ハーネス（ADR-0008）

- 移し終えたフォルダから順に、コードに文が直接書かれていないことを検査する（Grafana の ESLint の規則に当たるものを、`scripts/check.sh` の検査として作る。コメントとテストを除く）。
- 言語ごとの辞書のキーがそろっていること、差し込む値の名前が言語の間で同じことを検査する。
- 同じ辞書と値を Rust と TypeScript の両方の実装に通し、同じ文になることを結合テストで確かめる。
- **疑似翻訳**の言語（VS Code と同じく、文字を変えて 3 割ほど伸ばしたもの）を辞書から自動で作り、UI テストで、訳し忘れ（元の文のまま出ている所）と、幅のあふれを見つける。
- e2e と UI テストの基準画像は、日本語のまま撮る。英語の画面は、言語を切り替える主な流れだけを確かめる。

### 7. 文書

| 文書 | 英語と日本語 | 置き方 |
| --- | --- | --- |
| README・CONTRIBUTING・SECURITY | 済み（2026-11-13） | 英語を `*.md`、日本語を `*.ja.md` |
| マニュアルのサイト | 0.4.0 から | VitePress の言語の切り替え（`locales`）。Kubernetes・OpenTelemetry・VitePress 自身の文書と同じく（メンテナの判断、2026-11-14）、**英語を `/`、日本語を `/ja/`** に置く。今の日本語のページのパスには、`/ja/` の同じページへ移す案内のページを残す。言語の自動の選び方は 4 のとおり。版のフォルダ（安定版・プレビュー版）ごとに両方の言語を持つ |
| リリースノート | 0.4.0 から | 英語と日本語を 1 つのリリースに並べる（GitHub のリリースは 1 つしか本文を持てないため）。書き方は release のスキルで決める |
| 例のモデル・サンプル | 0.4.0 から | 英語の画面では、英語の名前のサンプルを開く（自分で作る。モックのサンプルは使わない） |
| 開発者向け（ADR・要求仕様・開発の手順・対応表） | 利用者向けが終わってから | 置き方は、そのときに決める |

### 8. 翻訳を受け付ける場（その先）

ほかの言語を足すときは、**Weblate のホスト版（libre プラン）**を第一の案にする。Weblate 自身がオープンソース（GPL）で、無料で使え、Penpot などのデザインツールが使っている。Crowdin（Grafana・Excalidraw）も OSS には無料だが、サービスそのものは非公開である。どちらも i18next の JSON を読めるので、2 の形は変えずに済む。決めるのは、ほかの言語を受け付けると決めたときにする。

## 決めたこと（メンテナの判断）

- 進め方：0.3.0 で土台、0.4.0 で英語版。文書は利用者向けを先に、終わってから開発者向け（2026-11-13）
- 言語の選び方：利用者の環境（ブラウザ・OS の言語の設定）から自動で選び、利用者が選び直せる（2026-11-13）
- 辞書の形：Fluent を、公式の実装で読む（2026-11-14 改訂。初めは i18next の JSON を自前の関数で読むとしていた）
- 元の言語：英語（2026-11-14）
- 問題一覧の文：コアは言語を知らず、文言の層（`modelith-messages`）が文にする（2026-11-14）
- マニュアルのパス：ほかの OSS に合わせ、英語を `/`、日本語を `/ja/`（2026-11-14）
- 英語の画面で SysML v2 の用語をどこまで言い換えるかは、0.4.0 で英語の手引きを書くときに決める

## 改訂（2026-11-14）：辞書の形を Fluent にする

初めは、i18next の JSON の形を借り、自前の小さな関数で読むとしていた。メンテナが、文にする処理を独自に実装することを気にかけ、比べ直した。

| | Rust（問題一覧の文） | TypeScript（画面の文言） |
| --- | --- | --- |
| i18next | 公式の実装が無く、自分で書く。英語と日本語のほかの言語では、複数形の決まり（CLDR）のデータも要る | 公式の `i18next` を使える |
| Fluent | 公式の `fluent-bundle`（Firefox が使う） | 公式の `@fluent/bundle`（依存なし） |

i18next では Rust の側を必ず自分で書くことになり、TypeScript の側と振る舞いが食い違うおそれが残る。Fluent は両方に同じプロジェクトの実装があるので、Fluent にする。翻訳のサービス（Weblate・Crowdin）は Fluent を読める。

採用の前に確かめたこと（2026-11-14）：

| 観点 | 結果 |
| --- | --- |
| 大きさ | wasm は gzip で約 68 KB 増える（`fluent-bundle` 0.16 だけを入れた wasm で測った。今のコアは約 533 KB）。TypeScript は gzip で約 4 KB |
| 文字化け | 日本語・英語・引用名・BMP の外の漢字・絵文字を含む文を、Chromium 156・WebKit（Safari 27.2 のエンジン）・Firefox 157 で文にし、3 つとも同じ文になった。ページとスクリプトに文字コードの宣言が無くても変わらない（モジュールと `fetch` の文字は常に UTF-8）。Playwright のエンジンで確かめたもので、macOS・iOS の Safari そのものでは確かめていない |
| 見えない記号 | 既定では値の前後に U+2068・U+2069 が入る。3 つのブラウザとも幅は変わらない（HTML・SVG・canvas）が、コピーした文・入力欄・ツールチップに残り、文字の検索に当たらなくなる。入れない設定にする |
| 複数形 | `Intl.PluralRules` と `fluent-bundle` で、日本語・英語・ロシア語の選び分けが同じ |
| 実装の違い | 数の書き方が違う（TypeScript は `1,234,567`、Rust は `1234567`）。文に出す数は文字列で渡す決まりにし、結合テストで両方の文を比べる |
| 脆弱性 | RustSec の一覧（2026-11-13 時点）に、`fluent-bundle`・`fluent-syntax`・`fluent-langneg`・`intl-memoizer`・`intl_pluralrules`・`unic-langid` の知らせは無い。依存の `self_cell`・`smallvec` の過去の知らせは、使う版で直っている。`@fluent/bundle` 0.19.1 は `npm audit` で 0 件。CI の `audit` が毎回確かめる |
| 手入れ | `fluent-bundle` は 2025-05、`@fluent/bundle` は 2025-04、`intl_pluralrules` は 2022-10 が最後の公開。更新はゆっくりだが、Firefox が使っている。`unic-langid` の `macros` の機能は、非推奨の crate を引き込むので使わない |

## 結果

- 0.3.0 のあと、文言を足すときは辞書に書く。コードに文を直接書くと、検査で止まる。
- 0.4.0 で、英語の画面とマニュアルを出せる。ほかの言語は、辞書を足すだけで加えられる。
- 要求仕様に、言語の要求（N-13、F-L10N-1・F-L10N-2）と、文言の層（Messages）を足した。
