# ADR-0029: 画面を開かずに PNG を書き出す

- 状態: 採用（2026-11-28）
- 日付: 2026-11-28
- 関連する ADR: ADR-0006（ライセンス）、ADR-0024（AI と共同編集の土台）、ADR-0028（npm のパッケージの名前）

## 背景

ADR-0024 の 1 で、外に出す操作の「図を書き出す」は SVG・PNG・draw.io とした。SVG と draw.io は 0.3.0-alpha.1 で入れた。
PNG は、「ブラウザの無い所で画面と同じ見た目が出るかを確かめてから足す」として残していた（メンテナの判断、2026-11-20）。

画面の PNG は、図の SVG をブラウザに描かせて作っている。CLI と MCP のサーバ（Node）にはブラウザが無いので、SVG を画像にする部品が別に要る。

2026-11-28 に、サンプルの図を、ブラウザ無しの描画の部品（resvg）と Chrome の両方で画像にして見比べた。

| 見たもの | 結果 |
| --- | --- |
| 形・配置・色 | 同じ。配置は文字の実際の幅に頼らず（幅は見積もりで決めている）、SVG は基本的な機能（図形・線・マーカー・文字）しか使っていない |
| 文字 | 動かす所に入っているフォントで変わる。画面の PNG も同じ（SVG はフォントを名前で指すだけで、フォントを含まない） |
| フォントが無い所 | 文字が 1 つも出ない画像が、エラーも無くできる。日本語のフォントの無い Linux のサーバやコンテナがこれに当たる |
| 速さ | サンプルの全体図（要素 44）で 0.2 秒ほど |

AI のクライアントから使う場面は、コンテナや CI が多い。そこで文字の出ない画像ができるのが、いちばん困る。

## 決定

### 1. SVG を画像にする処理は、Rust の resvg で作り、wasm にして CLI から使う

| 案 | 内容 | 判断 |
| --- | --- | --- |
| A. npm の既製品（`@resvg/resvg-js`） | OS ごとの実行ファイルを入れ、その所のフォントを使う | 採らない。フォントの無い所で文字が出ない。OS ごとの部品が 12 個要る。もとの resvg より古い |
| B. npm の既製品（`@resvg/resvg-wasm`） | wasm。フォントは渡す | 採らない。もとの resvg より古い（1 年ほど更新が無い）。描画の部品の版を自分で選べない |
| C. Rust の resvg を自分で wasm にする | 新しい crate（`crates/modelith-raster`）で resvg を呼び、wasm にする | **採る** |
| D. ブラウザを動かす（Playwright など） | 画面と同じブラウザで描く | 採らない。数百 MB のブラウザを入れることになる |

- 描くのは、画面と同じ SVG（`web/src/render`。ADR-0024 の 3 の B）。図の配置と描画は写さない。新しい crate は「SVG とフォントを受け取り、PNG を返す」だけにする。
- この crate は、コア（`modelith-core`）にも、ブラウザに配る wasm（`modelith-wasm`）にも入れない。別の wasm にして、CLI が PNG を書き出すときだけ読み込む。ブラウザのアプリの大きさは変わらない。
- resvg のライセンスは Apache-2.0 または MIT で、AGPL-3.0 の本体に組み込める（ADR-0006）。
- Rust で作るので、いずれ Rust の実行ファイルやサーバで画像を作るとき（ADR-0024 の 3 の A）にも、同じ crate を使える。

### 2. フォントは、CLI のパッケージに同梱する

- その所のフォントは使わない。どこで動かしても、同じ画像になる。
- 同梱するのは、Noto Sans JP の Regular と Bold（図の文字と、名前の太字）と、IBM Plex Mono の Regular（区画の行などの等幅の文字）。どれも SIL Open Font License 1.1 で、同梱と再配布ができる。ライセンスの文をパッケージに入れる。
- 同梱したフォントに無い文字（日本語と英語のほかの言語の文字など）は出ない。出せない文字があるときは、黙って欠けた画像を返さず、理由を添える。ほかの言語のフォントは、要望が出てから考える。
- フォントのファイルは、リポジトリに入れない（合わせて 9MB ほどあり、履歴に残り続けるため）。組み立てるときに、決めた版を、ハッシュを確かめて取ってくる（`wasm-bindgen` と同じ形）。
- CLI のパッケージ（`.tgz`）は、0.7MB ほどから 9〜10MB ほどになる（wasm が 1MB 弱、フォントが 8MB 弱）。

### 3. 画面の見た目との違い

- 形・配置・色は、画面と同じにする（同じ SVG から作る）。
- 文字の形は、画面と同じとは限らない。画面は見ている人のパソコンのフォントで描き、CLI は同梱のフォントで描く。Noto Sans JP が入っているパソコンの画面とは、ほぼ同じになる。
- 画面の PNG の書き出しは、今のまま（ブラウザに描かせる）にする。

## 決めたこと（メンテナの判断、2026-11-28）

- フォントは同梱する（その所のフォントを使う案は採らない）
- 描画は、Rust の resvg を自分で wasm にする

## 結果

- `crates/modelith-raster` を足す。`scripts/build-wasm.sh` で、コアとは別の wasm を作る。
- `modelith export --format png` と、MCP の `export_diagram` の `png` を足す（要求 F-AI-3）。
- `scripts/build-cli.sh` で、フォントと、そのライセンスの文をパッケージに入れる。
- 図の SVG に、resvg が扱えない書き方を足さない。足したときに気付けるよう、CLI の PNG のテストで見る。
