# 文言の辞書

画面の文言は、コードに直接書かず、言語ごとの辞書に置く（[ADR-0027](../adr/0027-languages.md)）。
言葉づかいは [画面の言葉の手引き](ui-writing.md) に従う。ここでは、置き場所と書き方を決める。

0.3.0 の間は日本語の辞書だけ。画面の文言（`web/src` と `web/index.html`）は、すべて辞書に移した。英語の辞書と言語の切り替えは 0.4.0 で足す。

## 置き場所

| もの | 場所 |
| --- | --- |
| 辞書 | `web/src/locales/<言語>/<場所>.ftl`（[Fluent](https://projectfluent.org/) の形）。場所は、文を主に使うフォルダ（`web/src` の下）の名前。`app` は大きいので、`app.ftl`（図とパネル）・`app-files.ftl`（ファイルの操作）・`app-inspect.ftl`（インスペクタと右クリックメニュー）・`app-plugins.ftl`（プラグインの画面）・`app-glossary.ftl`（語の説明）に分ける。画面の骨組みは `shell.ftl` |
| 文を受け取る口 | `web/src/l10n/index.ts` の `t(キー, 値)` |
| 辞書から文を作る部分 | `web/src/l10n/translator.ts`（Fluent の型に触れるのはここだけ） |
| 起動時に辞書を入れる所 | `web/src/l10n/setup.ts`（アプリは `main.ts` の先頭、コアの Worker は `core/worker.ts` の先頭、テストは Vitest の準備で読む）。`cli` は `cli/src/l10n.ts`（図に描く文の `render.ftl` と `core.ftl` だけを読む） |
| 検査 | `web/tools/l10n-cli.ts`（`scripts/check.sh` の静的検査で動く） |

問題一覧の文（Rust のコアが見つけるもの）は、`crates/modelith-messages` に置く予定（ADR-0027 の 3）。

## 使い方

```ts
import { t } from "../l10n";

toast(t("files-already-exists", { path }));
```

```
# web/src/locales/ja/files.ftl
files-already-exists = 「{ $path }」は既にあります
```

### 画面の骨組み（index.html）

`web/index.html` には文を書かず、キーだけを書く。辞書のファイルは `shell.ftl`。

```html
<button id="btnSave"><span data-l10n="shell-save"></span><span class="kbd">Ctrl+S</span></button>
<button id="btnUndo" data-l10n-title="shell-undo-hint" data-l10n-aria-label="shell-undo" disabled>…</button>
```

- `data-l10n="キー"`：要素の中身。その要素の中身は空にしておく。ほかの子（ショートカットの表示など）と並ぶ文は、`<span data-l10n="…"></span>` で囲む。
- `data-l10n-title`・`data-l10n-aria-label`・`data-l10n-placeholder="キー"`：その属性。
- ビルドのとき（開発サーバでは配るとき）に、元の言語の文で埋める（`web/tools/l10n-html.ts`、`vite.config.ts` の `l10nHtml`）。スクリプトを読み込む前から文が見える。
- スクリプトが起動時に必ず入れる文（版・開発段階の札など）は、`index.html` には書かない。

## 決まり

- **キー**は小文字の英字・数字・`-` だけで、「場所-中身」の形にする。場所は、辞書のファイルの名前と同じにする（`files.ftl` のキーは `files-name-empty`）。
  ほかのフォルダの文を使ってもよい（`workspace` が `files-not-found` を使う）。
  中身は、文の言い回しではなく、何を伝える文かを書く（言い回しを変えてもキーは変えない）。
- **キーは文字列をそのまま書く**（`t("files-name-empty")`）。組み立てたキー（`` t(`files-${kind}`) ``）は、検査が辞書と突き合わせられないので書かない。
  種類ごとに文を選ぶときは、キーを表に持つ（`{ part: "kind-part", port: "kind-port" }`）。
- **値の名前**は英字と数字だけにする（`{ $name }`・`{ $fileName }`）。
- **文に出す数は、文字列にして渡す**（`{ count: String(n) }`）。数のまま渡すのは、複数形の選び分けに使う値だけにする。
  数の書き方が、TypeScript と Rust の実装で違うため（`1,234,567` と `1234567`）。
- **文に `{`・`}` を書くとき**は、`{"{"}`・`{"}"}` と書く。
- **文を HTML として画面に入れない。** 訳は外から届くので、タグを書かれても動かないようにする。
  HTML に差し込むときは、これまでどおり `esc()` を通す。文の中にタグを書かず、太字やリンクにしたい部分は、文を分けて別のキーにする。
- **文をつなげて作らない。** 語順は言語で違うので、1 つの文は 1 つのキーにし、変わる部分は値で渡す。
- 同じ文でも、使う場面が違えば別のキーにする（言語によって訳し分けることがある）。同じ場面の同じ文は、同じキーを使う。
- 使わなくなったキーは、辞書から消す（検査が、使われていないキーを知らせる）。
- **引数や変数に `t` という名前を付けない**（文を受け取る `t` が隠れる）。
- モジュールの先頭（読み込んだ時点）で `t` を呼んで、表や定数に文を入れてよい。辞書は、どのモジュールよりも先に入る。
  その代わり、言語を切り替えるとき（0.4.0）は、ページを読み込み直す。
- **`web/src/render` と、そこから使う `web/src/core` の文は、`render.ftl` と `core.ftl` に置く。** `cli` が図を書き出すときに読むのは、この 2 つだけ。
  描画から、ほかの辞書のファイルの文を使わない。

## 辞書に移さないもの

- 図に描く記号（`«part def»` などのステレオタイプ）と、SysML v2 のキーワード。言語によらず同じに描く。
- 開発者だけが見る文（コンソールへの記録・`l10n` の層そのものの誤り）。英語で書く。
- テスト・コメント・doc コメント。
- 文字の種類を調べる正規表現など、文ではないもの。その行か、前の行のコメントに `l10n-ignore: 理由` と書くと、検査から外れる。

## 検査

`scripts/check.sh` の静的検査で、次を確かめる。

- 辞書のキーと値の名前が、決まりどおりの形か。キーが、辞書のファイルの名前で始まるか
- コードが `t("…")` に書いたキーが、辞書にあるか
- 辞書のキーが、どれもコードで使われているか
- 画面のコード（`web/src`）と画面の骨組み（`web/index.html`）に、文が直接書かれていないか（コメントは見ない）

## テスト

- 文を確かめるテストは、これまでどおり日本語の文で確かめてよい（e2e と UI テストの基準画像も日本語のまま）。
- 開発中とテストでは、辞書に無いキーや、足りない値があると、その場で例外になる。配った版では、キーをそのまま出して記録だけにする。
