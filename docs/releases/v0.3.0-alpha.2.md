# Modelith 0.3.0-alpha.2

0.3.0 の 2 つめのプレリリースです。AI や人が書いた SysML v2 のテキストを、読み落とさずに読めるようにしました。型を複数書いた部品、値を書いた列挙値、条件付きのインポートを読み、別の要素の説明として誤って表示していた不具合を直しました。

## 新しい機能

- 型を複数書いた要素：`part x : A, B;` のように型を複数書いた要素を、すべての型で読むようにしました。これまでは 1 つめの型（A）だけを読んでいました。図では型ごとに線を引き、図のタイトルとモデルのツリーに `x : A, B` と示します。見つからない型は、何番めでも問題一覧で知らせます
- 列挙の定義の値の一覧：図に出した列挙の定義（`enum def`）に、値を書いた順に並べるようにしました。これまでは、値が 1 つも書かれない空の箱でした。値を書いた列挙値は `low = 1` のように示します
- 条件付きのインポート：`import Lib::*[@Safety];` のように条件を書いたインポートは、条件に合う要素だけを取り込むようにしました。パッケージの中に `filter @Safety;` と書いたときも同じです。これまでは、条件を読まずにすべてを取り込んでいました。使える条件は、図の絞り込みと同じです（`@メタデータ` や種類の検査と、`and`・`or`・`not`・括弧）。値の比較を含む条件（`level > 1` など）はまだ扱えないので、問題一覧で知らせたうえで、絞り込まずに取り込みます。絞り込みが効くのは、フォルダを開いて複数のファイルを読んでいるときです

## 不具合の修正

- 関係に書いた説明が、別の要素の説明になる：`satisfy R by x { doc /* 理由 */ }` のように、関係や流れの文の中に説明やメタデータ（`@M;`）を書くと、外側のパッケージや定義の説明・メタデータとして表示していました。外側の要素には付けないようになりました。`flow`・`first … then`・`transition`・`verify` などの文でも同じです
- キーワードを書かない列挙値：列挙の定義の中の `mid = 2;` のように、`enum` を書かずに値を書いた列挙値を、列挙の定義の式として読んでいました。列挙値として読むようになりました。値を書いた列挙値（`enum high = 3;`）は、フェーズの並びに数えていませんでしたが、数えるようになりました
- ヘルプのコミットの番号と「ソースコード」のリンク：公開したアプリのヘルプに出るコミットの番号と、「ソースコード」「ライセンス」のリンクが、その版のものではなく、公開の作業をした時点の開発中のソースを指していました。その版のソースを指すようになりました。公開中の 0.1.0・0.2.0-rc.2・0.3.0-alpha.1 も、作り直して直してあります

## その他

- コマンドの npm への公開の準備：`modelith` のコマンド（`modelith-cli`）を、`npx modelith-cli` で使えるようにする準備を進めています。公開までは、これまでどおり、このリリースに添付した `modelith-cli-0.3.0-alpha.2.tgz` から入れてください（`npm install -g https://github.com/modelith/modelith/releases/download/v0.3.0-alpha.2/modelith-cli-0.3.0-alpha.2.tgz`）

## 0.3.0-alpha.1 をお使いの方へ

- 条件付きのインポート（`import Lib::*[@Safety];`）や、パッケージの中の `filter` を書いていたモデルでは、条件に合わない要素が取り込まれなくなります。その要素を型などに使っていると、「見つかりません」と出るようになります。使う要素は、条件を付けないインポートか、修飾名（`Lib::Seat`）で指してください

## ご注意

- 開発中の版のため、操作方法や保存形式は予告なく変わることがあります。
- 本ソフトウェアは無保証です。
- フォルダを開いてファイルを直接保存できるのは、Chrome と Edge です。
- 保存先のないファイル（新規作成したファイルやサンプル）は、ブラウザ内に下書きとして一時的に残るだけです。必要なものは「名前を付けて保存」で保存してください。
